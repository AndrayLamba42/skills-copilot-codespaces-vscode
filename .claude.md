# Claude Configuration — Skills Copilot Codespaces VS Code

> This file is read by Claude at the start of every session.
> It defines code style, workflows, bash commands, modular rules, and verification strategies.

## Project Overview

This is a **GitHub Skills** educational template that teaches developers how to use GitHub Copilot within VS Code Codespaces. Learners progress through steps by creating JavaScript files that are validated by GitHub Actions workflows.

**Key paths:**
- `.github/steps/` — Step instructions and progress tracker (`-step.txt`)
- `.github/workflows/` — GitHub Actions that validate learner progress
- Project root — Where learners create JS files (`skills.js`, `member.js`, `comments.js`)

## Code Style

### JavaScript
- Use `camelCase` for variables and functions
- Use `PascalCase` for classes and constructors
- Prefer `const` over `let`; avoid `var`
- Use template literals over string concatenation
- Add JSDoc comments for all exported functions
- Keep functions small and single-purpose (<30 lines)

### YAML (GitHub Actions)
- 2-space indentation
- Quote strings that contain special characters
- Use descriptive job and step names

### Markdown
- Use ATX-style headers (`#` not underlines)
- One sentence per line in source (for clean diffs)
- Wrap code examples in fenced blocks with language tags

## Bash Commands Reference

```bash
# --- Git Workflow ---
git status                          # Check working tree
git add <file>                      # Stage specific file
git commit -m "description"         # Commit with message
git push origin <branch>            # Push to remote

# --- Validation ---
cat .github/steps/-step.txt         # Check current tutorial step
ls *.js                             # List learner-created JS files

# --- Codespace Utilities ---
code <file>                         # Open file in VS Code
node <file.js>                      # Run a JavaScript file
npm test                            # Run tests (when package.json exists)
npm run lint                        # Run linter (when configured)
```

**To add a new rule:** Create a `.md` file in `.claude/rules/` and reference it in this table.

## Directory Structure Convention

When the project grows beyond the tutorial phase, organize files as follows:

```
project-root/
├── .claude.md                  # This file (session config)
├── .claude/
│   └── rules/                  # Modular rule files
├── src/
│   ├── helpers/                # Pure utility functions
│   ├── utils/                  # Shared cross-cutting utilities
│   ├── structures/             # Data structures and type definitions
│   └── services/               # Business logic modules
├── tests/
│   ├── unit/                   # Unit tests (mirror src/ structure)
│   ├── integration/            # Integration tests
│   └── fixtures/               # Test data and mocks
├── .github/
│   ├── workflows/              # CI/CD automation
│   └── steps/                  # Tutorial step content
└── docs/                       # Extended documentation
```

## Verification & Testing

- **Every new helper/util must have a corresponding test file** in `tests/unit/`
- Run tests before committing: `npm test` (when available)
- For data-heavy tasks, validate with fixtures in `tests/fixtures/`
- GitHub Actions workflows auto-validate tutorial step completion
